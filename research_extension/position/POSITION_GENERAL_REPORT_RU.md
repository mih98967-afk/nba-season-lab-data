# Позиции и сложность соперника: результат исследования 17.11.2026

## Решение

**Дополнительную общую поправку на соперника не принимаем: она проиграла исходному Ridge на заранее заданной development-проверке. Пять отдельных позиционных рейтингов пока не имеют исторически корректных меток.** Это не отменяет уже существующую пользу всей matchup-группы исходной модели: новый эксперимент проверял добавку сверх неё. `adopt_on_site=false`; текущие прогнозы, optimizer и Hosting не изменены.

## Что проверено практически

Сохранён исходный Ridge context с 82 признаками. Игроки, минуты/роль, темп и остальные предматчевые признаки остались одинаковыми. К нему по одному добавлялись две версии сглаженного остатка против конкретного соперника: фактические FP минус ожидаемые FP по строго предматчевой модели, с календарным half-life 60 дней и prior strength 50/150 взвешенных player-games. Нулевая поправка означает нейтральный эффект.

Для остатка не использовались прогнозы модели, обученной на тех же результатах: вспомогательный Ridge переобучался помесячно только на предшествующих датах, минимум 1000 сыгранных строк. Обновления residual выполняются после всех прогнозов текущей NBA-даты. Текущие минуты, текущий темп и outcome в признаки не подставляются. Следовательно, это quality/opportunity-adjusted предиктивная добавка; она не выделяет чистую причинную силу защиты независимо от ошибок минут и других факторов.

Development: train сезона 2023/24 → октябрь–ноябрь 2024; затем train по ноябрь 2024 → декабрь 2024. Критерий — pooled RMSE на 9704 сыгранных player-games. После выбора всё одинаково переобучено по 31.12.2024, поправка среднего калибруется 01–23.01.2025. Confirmation — 16.02–конец сезона 2024/25; аудит 2025/26 уже был раскрыт ранее и не называется независимым тестом. Исходы 2026/27 этот эксперимент вообще не открывает.

| Проверка | Исходный Ridge | + residual k50 | + residual k150 |
|---|---:|---:|---:|
| Development RMSE (9704) | **8.260112** | 8.262789 | 8.262911 |
| Development MAE | **6.470651** | 6.473333 | 6.473447 |
| Confirmation MAE (8673) | 6.431366 | 6.430832 | 6.430904 |
| Раскрытый audit MAE (25769) | 6.349007 | 6.348755 | 6.348749 |

Поздние микроскопические различия не переопределяют выбор: для k50 gain MAE на confirmation всего 0.000534 FP, 95% date-cluster bootstrap [−0.000074; 0.001189]; на раскрытом audit 0.000252 FP [−0.000137; 0.000650]. Доказанного практически полезного прироста нет. Нельзя выбирать k50 задним числом по этому audit.

## Почему PG против Dallas пока нельзя честно раскрасить

В трёх сохранённых исторических regular-season boxscore-таблицах 97079 строк. Поле позиции содержит 14760 G, 14760 F, 7380 C и 60179 пустых значений (61.99%). Это позиции стартовой пятёрки из NBA boxscore. PG/SG/SF/PF отсутствуют полностью; исторический starter C также не является подтверждённой Sports.ru позицией C. Назначать PG по G или переносить текущую позицию на прошлые годы означало бы придумать отсутствующую информацию.

Проверены имена и существующие публичные связи catalog_id→имя. Получен версионированный snapshot для **392 из 484** fantasy-игроков: C71, PG73, PF78, SF77, SG93; 92 остаются UNKNOWN. Все 392 NBA person_id уникальны. Сопоставление использует точные имена после нормализации диакритики/пунктуации, без fuzzy угадывания. Снимок применим только после настоящего observed_at и только в 2026/27; это catalog evidence, а не независимо подтверждённый официальный Sports.ru справочник. Он не используется для доразметки 1741 старых frozen прогнозов.

Контракт разрешения позиций закрывается как UNKNOWN при конфликте, неопределённой идентичности, неподходящем сезоне, раннем времени, просроченном effective interval или грубой NBA starter-позиции. Для будущего исследования есть отдельный POSITION_PROSPECTIVE_DATA_CONTRACT.md с форматами источников, paired ablations и условиями допуска календаря. Новых scheduled workflow или выдачи будущих прогнозов этот модуль не создаёт.

## Проверки и воспроизводимость

**14/14 тестов PASS:** отсутствие same-day/future leakage в residual и помесячных nuisance fits, корректные decay/shrinkage, явная UNKNOWN-семантика, запрет переноса позиций назад во времени, конфликты/истечение снимков, проверка источника и identity. Протокол зафиксирован до fitting. Сохраняются все три варианта, предсказания, веса, monthly train cutoffs, source/frame/protocol/code hashes и машинные отчёты.

Команды из корня проекта после создания общего исторического frame:

```bash
python3 research_extension/position/run_general_opponent.py
python3 -m unittest discover -s research_extension/position -p 'test_*.py' -v
```

Путь к исходному научному пакету можно изменить переменной NBA_RESEARCH_BASE; по умолчанию research_base. Аудит каталога принимает существующий публичный JSON через --catalog, либо сохранённый Hosting ZIP через --hosting-zip. Никаких private файлов он не читает.

## Доказательства

- PROTOCOL_POSITION_GENERAL.md — заранее заданная постановка и границы.
- results/GENERAL_OPPONENT_REPORT.json — все метрики, парная неопределённость, хэши.
- results/PREQUENTIAL_FITS.json — фактические сроки обучения каждого nuisance fit.
- results/POSITION_AUDIT.json — исходные количества и покрытия.
- results/FUTURE_POSITION_MAPPING.json — версии нынешних позиций и UNKNOWN.
- results/general_predictions.csv.gz и general_opponent_models.pkl — воспроизводимые результаты; модельные pickle предназначены только для доверенного локального исследования.
- results/tests_position_general.log — результат 14 проверок.

Раздел не измеряет P(play), вероятностные диапазоны, сумму недели или реальную выгоду замен. Его отрицательный результат не доказывает, что позиционные взаимодействия бесполезны; пока их нельзя корректно проверить на этой исторической разметке.
