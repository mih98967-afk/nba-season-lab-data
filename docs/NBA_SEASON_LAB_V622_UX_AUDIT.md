# NBA Season Lab 6.22 — UX-аудит и приёмка

Состояние: **PR-кандидат, не production**. Основа: опубликованная пользователем v6.21, PR #178 merged; исходная папка `site/hosting_v620` сохранена без изменений. Это НЕ разрешение на Firebase deploy.

## Принципы

- Пять основных задач: **Сегодня** (нужна ли замена?), **Замены** (KEEP / NOW / LATER), **Команда**, **Игроки**, **Календарь**. Второстепенные экраны и исследования не конкурируют с ними.
- Главный вопрос, затем 2–3 причины, затем действие. Вспомогательные метрики и методы раскрываются по запросу.
- Одинаковые размер текста, плотность, отступы, нейтральные тёплые цвета Claude-style; зеленый/красный только если действительно доказана направленность. Никаких недоказанных "лёгких" матчей в уверенной окраске.
- Горизонт 7/14/21/28 дней и время МСК сохраняются. Единый навигационный контекст без отдельного сайта, репозитория и Firestore writes.

## Не считать решённым без браузерной проверки

- Полный визуальный QA: 1440×900, 1280×800, 768×1024, 390×844, 320×700; нет горизонтальной прокрутки всей страницы и перекрытий.
- Открыть полный календарь, сложность по пяти позициям, раскрытие 30 клубов и возвращение к 10; проверить управление клавиатурой и screen reader.
- Проверить воспроизведение состояния: смена модели, ограничения, KEEP / NOW / LATER, все страницы без записи личных данных и без автоопераций.
- Отдельно проверить, что у предупреждений и у "н/д" корректная семантика. На мобильном проследить, что панель игрока прокручивается, а модальное окно закрывается.
- Проверить свежие публичные JSON, model-weight parity и дату выдачи непосредственно перед сборкой Hosting ZIP. Старый успешный тест v6.21 не делает новую CSS/JS версию проверенной.
- `p.minutes_projection` — временный *непрогнозный* ориентир. **Следующий научный шаг**: формальная модель E(minutes|plays), отдельно валидированная на реальном prelock holdout, с контрактом и датой; нельзя простым переименованием выдать последнее среднее за прогноз.

## Сохраняемые инварианты

- Никаких изменений вычислений `P(play)`, `E(FP|play)`, `E(FP)`, официального OUT, калиброванных интервалов и optimizer logic.
- `expected_fp = p_play × mean_if_play`; нельзя умножать дважды.
- Не складывать матчевые интервалы в недельный, UNKNOWN не считать DNP, локальный сценарий — не официальная доступность.
- Без Firestore/private profile payload, новых сервисов/платных провайдеров, автоматических замен или Firebase deploy.
- Статус research-only challengers и отсутствие доказанной экономической выгоды оптимизатора не меняется.

Код v6.22 изолирован под `site/hosting_v622`. Проверить синтаксис, существующие `test_*.cjs`, новый UX-contract test, исходный manifest и fixture browser matrix в PR CI.
