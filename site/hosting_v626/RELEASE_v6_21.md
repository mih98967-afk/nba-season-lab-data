# NBA Season Lab 6.21 — матчевые прогнозы и сложность календаря

Продолжение существующего сайта `nba-season-lab.web.app`, Firebase project `nba-season-lab` (Spark). Каталог, профиль, история замен и интерфейс «Сегодня → Замены → Команда» сохраняются.

## Новая модель в сайте

Для поддержанных игроко-матчей основной режим использует сохранённые `near_latest` / `long_latest`: matchup-aware Ridge для FP при выходе, calibrated CatBoost для участия и LightGBM для прогнозных квантилей. Веса не переобучаются при обновлении данных. В карточке отдельно видны FP при выходе, вероятность участия, FP с учётом пропуска и матчевые диапазоны 50/80/95%.

Устаревшая, неоднозначная или неподдержанная оценка не становится нулём. Доступность новой модели проверяется для каждого матча, с идентичностью игрока, соперника, команды и точного времени. Поддержанные строки используются в существующих advisory-сравнениях; прежняя формула доступна для сравнения и как явно обозначенный резерв. Для части дальних горизонтов диапазоны остаются предварительными и не допускаются в расчёт решений.

Точно сопоставленный свежий официальный OUT применяется отдельно к конкретному матчу. Он не переписывает исходные модельные значения. Более свежий подтверждённый статус снимает старый OUT. Questionable не превращается автоматически в произвольно выбранную вероятность. Ручные сценарии остаются отдельными от проверенной калибровки.

## Сложность соперников

Раздел «Календарь → Сложность соперников» содержит общую оценку и PG/SG/SF/PF/C, окна 7/14/21/28 дней, сортировку и фильтр команд состава. Количество игр и средняя сложность показываются отдельно. Неопределённое направление не окрашивается как уверенно лёгкое или тяжёлое. Неназначенные матчи NBA Cup не скрываются.

Позиционный инструмент описательный: его дополнительная прогностическая польза не подтверждена, поэтому он не корректирует FP. Общий эффект соперника уже учтён в Ridge и не прибавляется повторно. Диапазон неопределённости эффекта соперника не является прогнозным диапазоном результата игрока.

## Проверяемость и ограничения

- Ежедневный расчёт использует проверяемые бесплатные источники и неизменённые веса; новые документы травм не продлевают срок свежести устаревших игровых данных.
- Новые соответствия каталога и NBA ID требуют точных подтверждений из ростеров и публичных протоколов. Ошибочная история однофамильцев исключается; неизвестная личность остаётся неизвестной.
- Матчевые ожидаемые FP складываются. Границы отдельных матчевых интервалов не складываются. Недельные сценарные P10–P90 в старом планировщике остаются некалиброванными сценариями.
- Новая модель не доказывает экономическую выгоду замен. Для KEEP/NOW/LATER сохраняются отдельные требования к ценам, квоте, T−30, владению и официально зачтённым Sports.ru FP. Ручной минимальный fallback и локальный журнал уже доступны.
- Исторический replay, замороженные будущие прогнозы и новые текущие оценки сохраняют разное происхождение. Дополнительный day-EWMA и внутридневная CatBoost-модификация остаются исследовательскими сравнениями.

## Полный Hosting ZIP

Сборка требует совпадающие по SHA256 результаты проверки весов/прогнозов и фактической браузерной проверки desktop/mobile. Синтетический браузерный тест сам по себе не разрешает сборку. Полный архив содержит все статические файлы и свежие публичные JSON; `BUNDLE_MANIFEST_v621.json` фиксирует версию исходников и хеши состава.

GitHub Actions обновляет публичные прогнозы и проверяет сборку. Он не выполняет Firebase deploy. В архиве нет владельческого профиля, частных журналов, Firestore credentials или автоматических трансферов.

После загрузки проверенного `nba-season-lab-v6.21-hosting.zip` в домашнюю папку Firebase Cloud Shell достаточно одной команды:

```bash
NBA_LAB_RELEASE="$(mktemp -d)" && unzip -q "$HOME/nba-season-lab-v6.21-hosting.zip" -d "$NBA_LAB_RELEASE" && cd "$NBA_LAB_RELEASE" && firebase deploy --only hosting --project nba-season-lab
```

Дата/хеш фактической публикации сайта подтверждаются отдельно от merge PR и успешного CI.
